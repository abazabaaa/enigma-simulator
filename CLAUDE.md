# CLAUDE.md — enigma-simulator

Two things live here: the original NSA Python Enigma teaching notebook at the repo root (unchanged, historical
conventions: the FIRST rotor listed is the fast rotor, no ring settings, no double step) and the interactive course
in `web/` (Vite 8 + React 19 + TypeScript + Tailwind 4 + React Three Fiber). Python helpers are in `tools/`.
The design rationale is in `reports/Interactive Enigma teaching tools.md`; the build plan in `docs/PLAN.md`.

## Ground truth you must not get wrong
- Rotors are listed left→right as the operator sees them; the RIGHTMOST rotor is the fast rotor. Stepping happens
  BEFORE encoding. The middle rotor double-steps: from ADU with I II III the windows go ADV, AEW, BFX, BFY
  (the "ADU→AEV→BFW" sequence in some sources is wrong). Turnovers Q E V J Z (VI–VIII: Z and M); the notch is on
  the alphabet ring, so a ring setting shifts the wiring but not the turnover letter.
- `compose(p, q)` applies p FIRST: `compose(p, q)[i] === q[p[i]]`; Rejewski's AD is `compose(A, D)`;
  `conjugate(p, by)` is by⁻¹·p·by. Cycle structure is invariant under the plugboard (stecker) conjugation.
- Accuracy oracles: `tools/reference_enigma.py` (independent Python, passes AAAAA→BDZGO, rings BBB→EWTYX, the
  1930 manual message, Barbarossa 1941, U-264 M4, Scharnhorst, M4 Beta@A+B-thin ≡ M3 UKW-B), the exported
  `web/src/engine/__fixtures__/vectors.json` (GENERATED by `python3 tools/export_vectors.py`; CI fails if stale) and
  `tools/oracles/` (three-oracle agreement over 1,000 random configurations with @ondoher/enigma and py-enigma).
  Never edit `web/src/engine/**` without re-running all three.
- Positions are shown as letters, ring settings as 01–26 numbers; the ring and the wiring core are two layers.
  No letter ever encrypts to itself; encipher is an involution.

## Working in web/
- `npm run check` = typecheck + vitest + build + bundle budget + ownership check. E2E: `E2E_PORT=41NN npx playwright
  test --project=2d|3d|walk --grep <tag>`; `npm run e2e:walk`; `npm run review -- --grep <tag>` writes screenshots,
  console and axe artefacts under `review-artifacts/`. The config THROWS without E2E_PORT.
- `@playwright/test` is pinned to 1.56.0 to match the Chromium 141 build at /opt/pw-browsers in the dev container.
  NEVER run `npx playwright install` there (CI installs its own browser). Headless WebGL 2 works via SwiftShader
  with `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`; never use `--use-angle=gl` (no GPU).
- Tests assert STATE through `window.__enigma`, `window.__stage`, `window.__course` (and `window.__machine3d` with
  `?e2e=1`), never pixels. Bans enforced by `npm test`: no `waitForTimeout`, `test.only`, `page.pause`,
  `toHaveScreenshot`; no `console.log` in `src/` outside `src/debug`; every spec imports test/expect from
  `./fixtures` and carries a tag (`@smoke`, `@platform`, `@area:<x>`, `@chapter:<id>`, `@3d`, `@sync`, `@walk`);
  every `*.test.tsx` starts with `// @vitest-environment happy-dom`; no `Math.random` in gates/rules/crypto (use
  `lib/rng`); chapter scenes contain no `.solve(` and no 1900–1949 years (story facts come from `facts.ts` with
  https sources).
- One machine store (`src/state/machineStore.ts`); 3D, 2D and the DOM controls all read it. The 2D/3D layout is the
  operator's view (reflector left … keys/lamps right). `pathPoints` = 2 when nothing is drawn, 2 + 2·hops once drawn.
- Contracts in `src/contracts/**` are normative; `web/ownership.json` + `scripts/ownership-check.mjs` enforce which
  PR may touch which files (`OWNERSHIP_BASE=<base ref>`). Pages load lazily by NAMED export.
- Chapters: copy `src/chapters/i2-stepping/` (a real lazily loaded chapter) — `gates.ts` is pure and validated by
  the lint/guess-bot/purity tests (300 seeds, < 1 % guessable); every code gate is PAIRED with a typed prediction whose
  probe varies per instance (pasted agent code alone cannot open a gate); never draw an answer-bearing ghost during a
  question (anything in the instance is readable via `__course.gate()`); constant-answer items are "once";
  fallbacks start at hint level 0; prompts must stand alone (turnover letters, tables) because items also appear in
  the return-check modal; reveals fire in listed order; Facts need https sources.
- Budgets (gzip): entry ≤ 170 kB, 3D chunk ≤ 400 kB (never in the entry), effects ≤ 130 kB, chapter ≤ 80 kB,
  code editor ≤ 150 kB. `frameloop="demand"`, ≤ 120 draw calls, zero idle frames.
- On a 4-CPU box keep Vitest at `VITEST_MAX_WORKERS=2` and Playwright at `--workers=1`; 3D specs under SwiftShader
  are slow and timing tests flake above load average ~10 — measure durations in-page, not from Node.

## Process lessons (from building this)
- Stack the work: contracts first (an early `[contracts-v1]` checkpoint commit unblocks parallel PRs), then one
  pilot chapter before the other chapters, then chapters in parallel on a rolling merge-point branch.
- Every PR gets an independent review agent that walks the UI in headless Chromium, reads the screenshots and
  tries to cheat the gates; the reviews found real issues every time (390 px legibility, answer leaks, gaming
  loopholes, camera framing, label collisions). Verify a builder's "green" by re-running its checks yourself.
- Merge-point branches (`claude/enigma/07-base`, `claude/enigma/chapters-base`) carry merges of sibling PRs so
  each PR's own diff stays clean; resolve conflicts once, in the branch whose author wrote one side.
- Pages deployment needs the one-off repo setting Settings → Pages → Source = GitHub Actions; the `deploy` job runs
  on pushes to `master`.
